3. RPC SEGURA DE ESTOQUE EXISTENTE
- public.admin_adjust_inventory(p_variant_id uuid, p_quantity integer, p_note text) existe.
- A função interna private.admin_adjust_inventory valida auth.uid() e exige role='admin' em user_roles.
- Quantidade 0 é rejeitada.
- Atualização do estoque impede saldo negativo.
- Movimentação registrada automaticamente:
  - quantidade positiva => movement_type 'entry'
  - quantidade negativa => movement_type 'adjustment'
- A função retorna novo saldo.
- Permissões EXECUTE já existem para authenticated. A função valida o papel admin internamente.
- O painel deverá chamar a RPC para entradas e ajustes. Não deverá escrever diretamente em inventory ou inventory_movements.
- Não foi feita alteração dessa função nem de grants/policies.

4. POLÍTICAS RLS EXISTENTES — MANTIDAS
- categories: admin manage; leitura pública apenas de categorias ativas.
- products: admin manage; leitura pública apenas de produtos ativos.
- product_variants: admin manage/read; leitura pública apenas de variantes ativas de produtos ativos.
- inventory: admin SELECT; nenhuma leitura/escrita direta de clientes.
- inventory_movements: admin SELECT; sem acesso direto de clientes.
- user_roles: usuário lê apenas seus próprios papéis.
- profiles: admin pode ler todos; usuário pode ler/atualizar o próprio perfil.
- O acesso de admin é determinado por user_roles e auth.uid().
- Nenhuma policy, RLS, grant, role, chave ou função de segurança foi modificada.
